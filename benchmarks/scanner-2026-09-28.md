# Initial board scanning regression — 2026-09-28

The initial scanner and automatic move tracker previously used different visual features.
The initial scanner still used 16×16 signed, background-subtracted RGB and old v2 learned
samples. The new initial scanner uses the tracker's background-independent BoardVision
features, explicit empty-square detection, per-square uncertainty, and a local starter bank.

## Comparable result

Both implementations received the same earlier reference screenshot and its known piece
placement. No endgame image samples were added to either reference bank. The legacy scanner
learned its original descriptors in memory; the new scanner loaded the actual quantized
starter-bank resource shipped with the app.

| Measure | Legacy initial scanner | Current initial scanner |
| --- | ---: | ---: |
| Correct labels on the endgame image | 60 of 64 | 64 of 64 |
| Display/matching score | 92.1% | 87.0% |
| Explicit review markers | Not supported | a5 rook |
| Median prediction time | 7.755 ms | 9.281 ms |
| Minimum prediction time | 7.571 ms | 9.124 ms |
| Maximum prediction time | 8.179 ms | 9.376 ms |

Timing used an optimized `swiftc -O` executable on the same Mac, 12 repeated predictions
per implementation, after an initial prediction. It excludes image-file loading, scanner
initialization, screenshot capture, and engine analysis. BoardVision observation extraction
alone had a median of 8.888 ms in this run. The current scan takes about 1.526 ms longer;
this result demonstrates improved recognition on the fixture, **not a faster first scan**.
Automatic tracking/reconciliation timing is a separate measurement.
The script reports the upper middle observation for the even-sized 12-run sample.

The old scanner missed the rook on a5, called both kings pawns, and invented a pawn on f8.
The current scanner labels every cell correctly, while conservatively marking the a5 rook
for review because the nearest other piece appearance is relatively similar. Neither score
is a calibrated probability that the entire board is correct.

## Calibration and limitations

The endgame image was not used to generate reference templates. It was inspected while
calibrating the empty-square cutoff: a stale corner badge left foreground occupancy of
approximately 0.039, so the cutoff changed from 0.035 to 0.045. Accordingly this is a
**regression result**, not a blinded held-out evaluation or a claim of 100% accuracy on
arbitrary boards. The legacy comparison retrains from the same verified reference image;
it does not reproduce the user's potentially contaminated 312-sample saved bank.

The starter bank covers the classic piece theme visible in these fixtures. Other themes,
misaligned crops, obscured pieces, or transient effects may require explicit corrections.
Unknown or ambiguous appearances are marked for review; many easily recognized empty
squares cannot conceal an uncertain piece in the aggregate confidence calculation.
Learning rejects stale labels on visibly empty cells and unlabeled occupied cells atomically.
Geometry alone cannot independently validate a user's first rook-versus-bishop label;
subsequent explicit corrections replace conflicting personal samples.

Nine scanner regression tests cover both real images, both orientations, ignoring legacy
samples, atomic rejection, saved-sample reload, correction conflicts, unknown shapes, and
uncertainty on sparse boards.

## Reproduction and regeneration

Run from the repository root on macOS. The frozen legacy scanner is benchmark support only
and is outside the application target. Neither comparator modifies saved user templates.

```sh
swiftc -O -parse-as-library -module-cache-path .build/ModuleCache \
  Sources/ChessLens/ChessModel.swift \
  Sources/ChessLens/ChessEngine.swift \
  Sources/ChessLens/BoardVision.swift \
  Sources/ChessLens/BoardScanner.swift \
  scripts/ScannerBenchmark/LegacyBoardScanner.swift \
  scripts/ScannerBenchmark/main.swift \
  -o /tmp/chesslens-scanner-benchmark
/tmp/chesslens-scanner-benchmark --timing
```

An optional non-flag argument supplies the repository root when running elsewhere.
`--export` writes a regenerated archive to standard output using the known reference image
and current BoardVision code. Inspect that output and rerun the regression tests before
replacing the bundled archive, particularly after a descriptor-format change.
The archived generator was compiled and its regenerated output matched the shipped archive's
SHA-256 exactly during this handoff.

```sh
/tmp/chesslens-scanner-benchmark --export
env CLANG_MODULE_CACHE_PATH=.build/ModuleCache \
  SWIFTPM_MODULECACHE_OVERRIDE=.build/ModuleCache \
  swift test --disable-sandbox --filter BoardScannerTests
```
